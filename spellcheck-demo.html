Domain Dictionaries — spell check demo

Pick a dictionary below to load it via the proposed Spell Check Custom Dictionary API which is available in Chrome Canary behind a flag. The whole page content is editable below and has native spellcheck turned on, so once you click inside, CSS will mark some domain specific words as spelling errors. If you choose from the dropdown, the domain words from the selected dictionary should stop showing red underlines. Selecting a different dictionary removes the previous one's words before adding the new set — only one dictionary is "active" at a time in this demo. These words came from this repo containing many domain terms.

Mechanically, this page itself never calls addWords()/removeWords(). The dropdown just sets the href of a declared <link data-spellcheck-dictionary> tag, and spellcheck-dictionary-loader-complete.js — loaded once in <head> — watches that tag via a MutationObserver and does the fetch-and-swap automatically. It's the same loader described in the project README, exercising its live href-change handling specifically.

Running this locally: this page loads dictionary files with fetch() (both from spellcheck-dictionary-loader-complete.js itself, and separately from this page's own script just to display a word count), which browsers block over a plain file:// URL. Serve this folder with a simple local server instead, e.g. python3 -m http.server, then open http://localhost:8000/spellcheck-demo.html.

About the API: document.spellCheckCustomDictionary has two methods .addWords(arrayofwords) and .removeWords(arrayofwords). It is a proposal, not yet implemented in any shipping browser. It is available in Chrome Canary and is scheduled for release behind a flag in DevTrial on Chrome desktop 153. In browsers without it, the dictionary calls below simply do nothing — dictionary words will still show as misspelled regardless of which option is selected. The badge above reflects real-time feature detection.
